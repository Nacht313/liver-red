# 設計：Godot 版開場（家裡 → 下樓出發）

日期：2026-11-07
狀態：策劃已確認（2026-11-07）

標記說明：沒有特別標記的是策劃說的；標 **［我的決定］** 的是 Claude 替策劃先做的選擇，策劃可以推翻。

---

## 1. 為什麼要做

網頁版開幕（`index.html`）的流程是完整的，但玩起來太簡陋：介面、版面、動態、字體、美術都撐不起來，也完全沒有音樂和音效。

策劃和一位朋友想**一起在 Godot 裡**開發這款遊戲，把整個流程用高品質重做一次，之後再把設計構想一步一步做完。兩人都是 Godot 和程式的**完全新手**，沒有固定分工。程式由 Claude 寫。

這一版要做到兩件事：

1. 開場本身好玩、好看、好聽。
2. 打下之後所有章節都能沿用的基礎：場景、對話、判定、日記本、手機、背包、存檔、資料格式。

## 2. 範圍

**只做開場：從主角在家裡醒來，到走出家門、下樓、正式出發為止。**

不做：機場、飛機、陸路、入境、曼谷。玩家下樓出發後，畫面收在一張「旅程開始」的結尾卡；出發時的狀態（錢、背包、訂好的票和住處、學到的知識）存起來，給下一章接著用。

## 3. 目標、不做的事、做出來也算失敗的事

### 目標

- 感覺像 **Undertale／Deltarune 的開場**，但做成**橫向捲軸**：像素場景、角色會走、走到東西旁邊按鍵互動、Undertale 式對話框。
- 網頁版開幕裡「在家準備出發」的規則全部保留，行為以網頁版和原型為準：時間和天數、數值、上限鎖、錢、旅行知識、日記存檔、家人訊息、思想櫃、訂票訂房、網購、打包、辦手續、錯過出發日。
- 有音效，有背景音樂。
- 兩個新手打得開、跑得起來、改得了台詞和數字。

### 這一版不做

- 開場以後的任何地點。
- A 股（手機上的股票 App）。**［我的決定］**：股票是大系統，等主線章節穩定後再做。
- 背包重量對走路速度的影響。家裡的路很短，感覺不出來；等出門的章節再做。
- 打包成可以發佈的 Mac 或 Windows 安裝檔。

### 做出來也算失敗

- 看起來還是像網頁選單：一排按鈕、選項清單。
- 判定欄或日記本常駐在畫面上。它們只在需要時出現。
- 對話一次整段跳出來，沒有逐字顯示和說話聲。
- 玩家看得到開發用語，例如「demo」「測試」「尚未實作」。
- 簽證、物價、規定和網頁版的資料對不上，或沒有標來源。
- 你們兩個打開專案就報錯，或不知道怎麼按「執行」。

## 4. 畫面和手感

### 主畫面：家，橫向捲軸

- **［我的決定］**：家是同一層樓的公寓。中國城市家庭多半如此。從左到右依序是：
  1. **我的房間**：電腦（查資料、訂票、訂房、網購）、床（睡覺、寫日記存檔）、背包（打包）、窗戶、書桌上的東西。
  2. **客廳**：電視、沙發、爸爸。
  3. **飯廳／廚房**：飯桌、媽媽、冰箱。
  4. **大門**：出門辦事（銀行、跟朋友吃飯）；出發當天從這裡出門。
- 大門外是**樓梯間**：鄰居、樓道小廣告、樓下的快遞櫃（網購到貨在這裡拿）。走下樓、走出社區大門，就是出發的那一刻。
- 鏡頭跟著主角水平移動。房間之間用門框分隔，可以直接走過去。
- 操作：鍵盤 ← → 走路，E 或 Enter 互動，數字鍵或方向鍵選選項，J 打開日記本，P 拿出手機，Esc 關閉。**［我的決定］**：先只做鍵盤，滑鼠可以點選項；手機觸控不在這一版。

### 標題畫面和開頭

- **［我的決定］** 有標題畫面（像 Undertale：黑底、像素標題字、少少幾個選項）：新的旅程、讀取日記、清除存檔。顯示「你記得 N 條旅行知識」（跨輪保留，沿用網頁版）。
- **［我的決定］** 開頭不是過場動畫，而是可以操作的：主角在深夜的房間裡（拒信、畢業證書的自言自語），走到飯廳吃晚飯，飯桌對話裡選旅費，回房間睡覺，隔天早上日期卡出現，開始準備。

### 出門辦事

- **［我的決定］** 銀行換匯、領現金、跟朋友吃飯都是「出門辦事」：在大門按 E 選要去哪裡，畫面淡出，用一張文字卡交代經過（花多少時間和錢、發生什麼事、要判定就跳出判定欄），再淡入回到家門口。這一版不畫銀行和餐廳的場景。

### 結局（失敗）

- 網頁版在家裡可能觸發的結局都保留：錢花完、精力歸零、信念歸零。結局畫面用黑底和大字，可以回到日記或重新開始；旅行知識保留。

### 對話框（Undertale 式）

- 畫面下方黑底白框，左邊有說話者的頭像。
- 文字逐字出現，每個字有「嘀」的說話聲。不同角色的聲音音高不同。
- 按鍵可以跳過逐字效果；文字顯示完後，按鍵進入下一句。
- 選項出現在對話框裡，用方向鍵或數字選。
- **跟物品互動時，主角會自言自語說出回憶**，例如看到書桌上的畢業照、牆上的獎狀、冰箱上的便條。這些台詞由 Claude 先寫草稿，策劃之後改寫。

### 判定欄（極樂迪斯科式，平常不出現）

- 只在需要判定的時候，從畫面**右邊滑進來**，蓋住一部分場景；判定結束就滑回去。
- 內容：屬性名稱和等級、成功率、屬性「插話」的內心聲音、選項（判定選項標成功率）。
- 擲骰的結果要演出來：數字跳動、成功或失敗的音效。
- **［我的決定］** 開場裡原本是純隨機的事件，改成判定：
  - 跟朋友吃飯告別：共情判定，決定信念加還是扣。
  - 讀書練英語：學識判定，決定學識會不會加 1。
  - 仔細讀沙發衝浪主人的檔案：共情判定。
  - 晚飯時跟爸媽談出國：一次膽識判定（新內容，台詞由策劃改寫）。

### 日記本（《最後生還者 2》Ellie 的日記，平常不出現）

- 隨時按 J 掏出來，**全螢幕**：左頁是主角的感想，右頁是照片，可以左右翻頁。
- 感想由遊戲依照發生的事自動寫入，例如決定出國、選了旅費、跟朋友吃飯、錯過出發日。**［我的決定］**：文字先由 Claude 寫草稿，策劃改寫。
- 照片：家裡有幾個能拍照的地方，例如窗外夜景、飯桌、自己的房間。用手機拍，耗電。
- 睡前在床上寫日記就是存檔，沿用網頁版規則。

### 手機（平常不出現）

- 按 P 拿出來，畫面中央出現一支像真手機的介面，背景場景變暗。
- 開場會用到的 App：
  - 地圖：亞洲地圖，選第一站，這一版只有曼谷能選。
  - 瀏覽器：查資料，8 個主題。
  - 旅行：訂交通、旅遊保險。
  - 訂房、沙發衝浪、購物。
  - 聊天：家族群。
  - 入境：TDAC、eSIM、寮國電子簽。
  - 銀行：看餘額。換匯和領現金要出門去銀行。
  - 相簿：看照片。
- 在家有 Wi-Fi；手機會耗電，在家可以充電。
- 電腦和手機做的事有部分重疊。**［我的決定］**：電腦開的是同一套 App，只是換成大螢幕的外框，而且用電腦不耗手機電量。

### 背包（格子背包，平常不出現）

- 走到房間的背包旁邊按 E 打開。全螢幕：左邊是床（還沒裝的東西攤在床上），右邊是大背包的上中下三層、隨身小包、腰包、褲袋的格子。
- 物品**拖進格子**擺放，可以旋轉，會顯示總重、手提行李重量、重心不穩的警告。
- 格子尺寸和物品形狀照原型（`prototypes/liver-red-demo-v3.html` 的 `SIZE`、`GRID`）。

### 時間和光線

- 時間規則沿用網頁版：一天分段、每個動作花時間、在家休息到下一段時間、晚上才能睡覺。
- **同一個場景只用一張底圖，時段由程式打光**（CLAUDE.md 第 2 條）：白天、黃昏、晚上、深夜窗外的天色和室內燈光不同，前景和背景吃同一套光線。
- 每天早上出現 P5 式的日期卡：日期、星期、天氣、距離出發還有幾天。這張卡在網頁版原型裡就有。

### 美術

- 像素風。場景解析度 **［我的決定］**：480×270，整數倍放大到視窗大小（1920×1080 是 4 倍）。
- 圖片由 Claude 用本機 Anima 模型或 gpt-image-2.5 生成，再用 `tools/art/` 的腳本縮小、收色、去背。流程見 `docs/art-pipeline.md`。
- 需要的圖：家裡的長條背景（白天一張，其他時段打光）、樓梯間、社區大門；主角、媽媽、爸爸、鄰居的走路和站立影格；頭像；可互動的物品；手機和日記本的外框；日期卡。
- 字體 **［我的決定］**：繁體中文像素字型用「俐方體 11 號（Cubic 11）」或「縫合像素字體（Fusion Pixel）」，兩者都是 OFL 授權，可以免費商用。動手時兩個都試，挑清楚的那個。

### 聲音

- **音效全部用程式合成**（Undertale 風格）：說話的「嘀」聲（每個角色音高不同）、腳步、開關門、按鍵選擇、確認、取消、判定擲骰、判定成功和失敗、翻日記本、手機點擊、拍照快門、蓋章、拉背包拉鍊、日期卡出現。
- **背景音樂從 OpenGameArt 找 CC0 授權的曲子**，先找 2 到 3 首：家裡白天、家裡晚上、出發。每首下載前先跟策劃確認檔名、來源和大小；授權和作者寫進 `CREDITS.md`。音樂現在不急，可以晚一點補。

## 5. 資料和內容

- 網頁版的資料表（`src/story/opening/data.js`）搬過去：旅行知識、查資料主題、物品、背包分層、交通、住宿、沙發衝浪主人、第一站、家人訊息、結局、小貼士。數字不變，來源待查清單照舊（`docs/research/opening-sources.md`）。
- **［我的決定］** Godot 版的資料用 JSON 檔，放在 Godot 專案的 `data/` 資料夾。理由：網頁版的資料已經能轉成 JSON；兩邊可以共用；新手用文字編輯器就能改；之後要做編輯工具也容易。
- 台詞（對話、自言自語、日記草稿、判定的內心聲音）放在獨立的資料檔，策劃可以直接改，不用碰程式。
- 介面文字一律台灣繁體中文、台灣用語（CLAUDE.md 第 4 條）。
- **之後要能翻譯成其他語言**（策劃要求）：
  - 玩家看得到的每一段文字都用「文字代號」引用，不直接寫在程式或場景裡。
  - **［我的決定］** 用 Godot 內建的 CSV 翻譯表：一列一個代號，一欄一種語言（先只有 `zh_TW`）。新手可以用試算表打開編輯；要加英文，就多開一欄。
  - 有數字或名字的句子用佔位符（例如「你換到了 {amount} 泰銖」），不拼接字串，因為不同語言的語序不同。
  - 字型要能換：每種語言可以指定自己的字型。
  - 台詞資料（JSON）只放代號和規則，文字本身在翻譯表裡。
  - 測試會檢查：每個代號都有中文、程式和場景裡沒有寫死的中文。

## 6. 和朋友一起開發

- 兩人都安裝 **Godot 4.7.2**（版本必須一樣）。
- **［我的決定］** Godot 專案放在這個 repo 的 `game/` 資料夾。網頁版留在原處當參考，和 `prototypes/` 一樣不再加功能。
- **［我的決定］** 用私人的 GitHub 倉庫共享，用 **GitHub Desktop**（圖形介面）同步，不用學指令。這需要策劃建立 GitHub 帳號和倉庫、邀請朋友，Claude 會寫一步一步的說明。推上 GitHub 之前會先問策劃。
- **兩個人主要都用 Claude Code 開發**（策劃補充）。所以 `game/CLAUDE.md` 要寫清楚給 Claude 看的規則：專案結構、資料和翻譯的格式、怎麼跑測試、不能違反的規則。不管誰的 Claude 接手，做法都一致。根目錄的 `CLAUDE.md` 也要指到這份。
- 寫一份新手說明 `game/README.md`：怎麼安裝 Godot、怎麼打開專案、怎麼按執行、怎麼改台詞和數字、怎麼同步、兩個人同時改同一個檔案時怎麼辦。

## 7. 怎麼確認做對了

- 遊戲規則寫成不碰畫面的程式，可以不開視窗直接跑測試。網頁版那 56 項測試裡，屬於開場的部分搬過去：資料檢查、數值規則、存檔、錯過出發日、網購到貨、打包重量。
- **［我的決定］** 不裝測試外掛，用 Godot 的無視窗模式跑測試腳本，指令寫在 `game/README.md`。
- 每個階段結束時，Claude 實際開遊戲，從頭玩到出發，截圖給策劃看。

## 8. 交給動手的人決定

- 程式怎麼分檔、場景樹怎麼排、用哪些 Godot 節點。
- 判定的成功率公式（網頁版有 `chanceOf`，可以沿用）。
- 動畫的時間長短、緩動曲線、合成音效的具體音色。
- 生成圖的提示詞和後處理參數。
- 日期卡、手機 App、日記本的細部版面（照本文件的方向）。

## 9. 策劃已決定

1. **主角是男性。** 所有角色圖、頭像都照男性主角畫，台詞用「他」。女性主角等遊戲完整之後再補，因為會帶出專屬的特殊事件。**［我的決定］**：程式裡把性別當成一個設定值，台詞資料可以依性別分支，之後補女性主角時不用改程式架構；這一版只寫男性的台詞。
